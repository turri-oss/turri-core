<conformance-tests>
Conformance tests are black-box tests that start the built software and check it from outside, against the scenarios of a functional spec's test plain file - written by turri's agents once the code is built, and run with the whole suite each time more lands, so nothing that worked quietly breaks. Unit tests are always written with the code; conformance tests are the project's choice: `conformance-tests:` in config.turri.yaml.
They are off here (conformance-tests: false, or unset). They make each change take about twice as long, so the person
keeps them off to iterate fast, and turning them on is theirs alone. While off, no conformance tests are written or run,
no conformance testing script either, and conform is refused. Test plain files already there are
kept, and not tested. When you think conformance tests are worth it here - the person asks for tests, a functional spec
could go wrong silently, or the coding agent keeps failing at one - tell them in a line or two why, and what it costs.
They decide, and turn them on with /conform - which also tests what is built - or /settings conformance-tests true.
</conformance-tests>
